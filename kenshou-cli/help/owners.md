# Owner records

`kenshou owners status` lists every owner record that the registered scenarios' known defects and your findings files cite. An owner record is a bug report or improvement request, written as an OKF concept, in the repository that owns the broken behavior. Each record block shows the canonical reference, the resolution (`resolved`, `unresolved`, or `not-a-record`), and the owner's `status`, `affectedVersion`, `fixedVersion`, and `lastWorkingVersion` exactly as written. It also shows the canonical record when the reference is a duplicate, and the scenarios and findings that cite it. The report states what the owner claimed when the bytes were read. It does not verify that claim, and it never writes to an owner's files.

A reference counts as an owner record only when it has the form `mori://NAMESPACE/PROJECT/okf/BUNDLE/concepts/HANDLE` and the concept's `type` is `Bug Report` (handle `bugId`) or `Improvement Request` (handle `requestId`). A plan URI, an `https://` link, or a concept of another type is reported as `not-a-record`. A record is matched by the handle in its frontmatter, never by its file name. Duplicate chains are followed to the canonical record; a cycle, a missing target, a missing record, and a field of the wrong type are each reported with a structured reason. Version fields are classified as `released`, `unreleased`, `unknown`, `unparseable`, `malformed`, or `absent`.

`--findings FILE` adds the citations in a `kenshou.owner-findings/v1` document and may repeat. `--map PREFIX=DIR` resolves references under the bundle URI `PREFIX` from the local bundle directory `DIR` and may repeat. Any other `mori://` reference is resolved with `mori path`. Live reads record the checkout revision and dirty state of each file read; `--no-git-provenance` leaves them out. `--json` prints one `kenshou.owner-status/v1` document. One diagnostic line per unresolved, cyclic, or malformed record goes to standard error.

`kenshou owners snapshot --out DIR` takes the same source options, resolves once, and writes a new directory with `snapshot.json` (`kenshou.owner-snapshot/v1`) and the exact record bytes under `records/`, named by their SHA-256. It refuses a directory that exists. Use `--no-git-provenance` for a snapshot you will check in. `kenshou owners status --snapshot DIR` reports from those bytes and runs no source, resolver, or enrichment. It cannot be combined with `--findings`, `--map`, or `--no-git-provenance`.

`kenshou owners reconcile --snapshot DIR --package-map FILE` compares each known defect's cohort scope with the version claims of the owner record it cites, as the snapshot holds them, and prints one finding per individual defect. The package map (`kenshou.owner-package-map/v1`) is yours: for each owner project (`affects`) or single record (`reference`) it names the cabal `packages` the defect lives in and, in the required `versionsApplyTo`, those of them whose version numbers are the ones the owner writes. A finding is a contradiction (`missing-upper-bound`, `bound-above-fixed-version`, `bound-below-fixed-version`, or `speculative-bound`), a warning that asks for your input (`no-owner-claim`, `unmapped-owner`, `ambiguous-package-mapping`, `unsupported-claim`, `fix-unreleased`, `owner-version-not-package-version`, or the secondary `scope-package-not-mapped`), or `consistent`. A contradiction carries a proposed scope: a `version-below` bound set to the owner's released fixed version, or a bound removed that no owner claim supports. Labels, source conditions, and revisions are never changed. `--catalog FILE` reads the declarations from a `kenshou.scenario-list/v1` catalog instead of the registered scenarios; `--json` prints `kenshou.scope-reconciliation/v1`. Warnings are repeated on standard error. The command reads its inputs only and writes nothing but its report.

## Fix verification

`kenshou owners dispositions --snapshot DIR --package-map FILE` derives per-owner, per-cohort conclusions from run evidence. It attributes runs through the registered scenario declarations or `--catalog FILE`. A `verified-fixed` conclusion requires a compatible, confirmed pass for every required scenario on a cohort containing the released fix. The report shows the owner claim, the applicable scopes, the evidence trust, and the runs behind the conclusion.

`--bundle DIR` selects the verification bundle. It defaults to `KENSHOU_EVIDENCE_BUNDLE` or `docs/verification` in the standard program. `--run-data DIR` locates linked results at `DIR/RUN_ID/run-result.json`. Use `--runs DIR` for additional sealed local runs in that directory's immediate subdirectories. Repeat it for multiple directories. `--coverage FILE` accepts an object mapping canonical owner references to arrays of required scenario IDs.

`--write-input FILE` saves a new `kenshou.disposition-input/v1` document. `kenshou owners dispositions --input FILE` replays that document. Both modes accept `--json` for `kenshou.dispositions/v1`. The report does not gate the exit code. Capture refuses to replace an existing input file.

Exit codes are 0 when the report was produced, whatever it contains, 2 for a usage error or an existing snapshot or input destination, and 4 when a source fails, or when a findings file, package map, catalog, snapshot, or disposition input cannot be read or fails its digest check. `owners reconcile` exits 1 when at least one finding is a contradiction.
